# docs-rules.md — the `replica/` document map, and the project's operating rules

**For:** a worker who has read `replica/AI-BRIEF.md` and is about to touch anything. This makes the project's memory findable and states each rule with the file+section it comes from. Verified against disk 2026-10-15; line counts from `wc -l replica/*.md`.

Every rule below already exists in `replica/`. This is the index, not a new authority — if this file and the doc it cites disagree, **the cited doc wins**, and the disagreement gets recorded in `recon.md`'s struck-through style (rule 2), never silently picked.

## 2. THE OPERATING RULES (8)

### Rule 1 — Never fabricate: every claim traces to a command + its output, and "unverified" is a valid answer
`proofs-ntp.md`: "Every claim below traces to a command and its output … where a check could not be run, that is recorded as a limitation rather than smoothed over." The same convention runs through `proofs-pkg.md` (failures "listed under 'Limitations'"), `proofs-shell.md` ("a future reader can re-run what we ran"), `proofs-desktop.md` ("a proof that only shows green is not a proof"), `test-report.md` (undrivable flows recorded as **BLOCKED with the cause named**, plus a "What I could NOT test, and why" section), `patches/README.md` step 1 ("If you cannot ground it, **do not write the patch** — a fake patch is worse than none"), `proofs-cpp-privacy.md` §1 ("**Zero patches authored. Zero apply-evidence.** That is the honest headline"), `re-deep-sync.md` ("`UNVERIFIED` = could not reach it; never guessed") and `recon.md` ("no attempts were made to fabricate one", kept struck through with the correction beside it). **Consequence** (`AI-BRIEF.md` §1): "Never claim something a proof doc does not already show." Where a number does not exist, the honest value is a stated non-measurement — `resource-budget.md` reports idle CPU as **CANNOT ASSESS** with the headless-compositor reason, not as a number.

### Rule 2 — The standing-note rule: every change/deletion leaves why-it-was-done, plus a pointer to the proof doc
- **Struck through in place, never deleted.** A contradicted claim becomes `~~wrong claim~~` with the correction and its confidence class beside it. Source: `evidence.md` "How to read a contradiction" rule 2; worked examples in `recon.md`, `parity.md` §2/§5 (`~~…~~ → **CLOSED 2026-10-15**`), `test-report.md`'s `Update 2026-10-15` banner that preserves the pre-fix verdicts.
- **Findings survive the fix.** `compile-readiness.md`: "The original findings below are preserved verbatim — they are the diagnosis, and the record of what was wrong." `deep-fork.md` keeps the pre-decision note "preserved because it was the accurate status when written".
- **A deletion leaves a comment naming the reason and the evidence.** `proofs-fix-prefs.md` §4: the comment above `DISABLED_APIS` "records every deleted API and why … plus the sensor addition's rationale with the `nsGlobalWindowInner.cpp:3622-3635` citation. All of it points at `replica/proofs-cpp-privacy.md`." Its table column reads "DELETED (comment left at each site)".
- **Superseded work gets a retired marker.** `brand/MASCOT.md`: the teal recolour "is **superseded** … Any audit that asserted 'zero warm-orange pixels in the mascot' … is **retired**."
- **The reason is never optional, even for a deletion** — `search-plan.md` §6 "Why not B (stated so it is not re-litigated every quarter)".
- **The rule's purpose, in the project's words** (`AI-BRIEF.md` §6.6): write findings into `replica/` (`proofs-<area>.md`, and update `evidence.md` / `parity.md` if a row moved) "so the next worker inherits them — that is the co-owner's rule this file exists to serve."

### Rule 3 — No user-requested features. Parity rows only; reviews can deprioritize, never add
`AI-BRIEF.md` §3: "**No user-requested features** — Parity rows only. Reviews (`fixes.md`, `reviews.csv`) **can deprioritize, never add**; the `user feedback` area (14 rows) is the only Ziy-own addition and is research backlog, not a build request" (cited to `parity.md` §3, `fixes.md` §4). `parity.md` §3 confirms the 14 `user feedback` rows are "Ziy's own additions from the review corpus, not Brave's feature set", and that `parity.py` excludes them entirely. `fixes.md` §4 keeps every plan item review-derived and records the cut ones as **ARCHIVED** with the co-owner's decision and date. The corollary in `features.csv`: a review may move a row's position in the plan; it cannot add a row.

### Rule 4 — The cut list is final. Do not rebuild any of it
**AI assistant (Leo), crypto wallet, rewards/ads economy (BAT, notification ads, sponsored backgrounds), VPN, and the wallet sidebar** — all cut, "not deferred, not partial". 36 `cut` + 12 `skip` rows. `AI-BRIEF.md` §3: "co-owner 2026-10-14: `replica/fixes.md` §1.1/§1.5 and the ARCHIVED note at §4.6; `replica/parity.md` §1 (wallet 13, sidebar 4, rewards 11, vpn 5 all cut)". `parity.md` §3: "36 cut rows (wallet, rewards, VPN, the wallet sidebar, the AI answer) and 12 skip rows … Those are decisions with names on them in `replica/fixes.md`, not gaps." `diff-summary.md` §3 lists the same set; `deploy.md` "Deliberate product decisions, not gaps" repeats it and points at `features.csv`'s `cut` rows. **`skip` (12 rows — Widevine, site isolation, BAT rails, Guardian's backbone, Mojo, Skia, P3A, Brave's account system, Brave's ad marketplace) means *uncloneable by nature*, not *removed by decision*** — `recon.md` "Out of scope" gives the per-row reason.

### Rule 5 — Process hygiene: throwaway `/tmp/ziy-*` profiles, anchored kills only
The project path contains `brave`, so a broad process pattern matches the user's own apps — a bare-word `pkill` once nearly killed the user's LibreOffice.
- `tools/lib/common.sh`: "Process hygiene. The project directory contains 'brave'; so do the user's LibreOffice and Firefox sessions. Everything we start MUST be selected with an anchored pattern that only matches a throwaway profile under `/tmp/ziy-*`, or by a PID we recorded ourselves. **Never `pkill -f firefox`, never `pkill firefox`.**" Helpers: `ziy_pids_of`, `ziy_kill_throwaway` (match → `kill` → sleep 1 → `kill -9`).
- `tools/verify.sh` header: every launch uses an explicit `--profile` under `/tmp/ziy-*`; only anchored `pgrep -f` on that throwaway path or self-recorded PIDs are killed; "the user's own Firefox/LibreOffice sessions are never matched, because the pattern contains `/tmp/ziy-` and nothing else". The `cleanup` trap only ever calls `ziy_kill_throwaway '/tmp/ziy-.*profile'`, and a dedicated check proves the harness never came near a user session.
- `replica/test/regressions.sh` header: "every kill is anchored: `pgrep -f '/tmp/ziy-.*profile'` by PID; the user's own Firefox (WhatsApp) and LibreOffice are never matched (the project directory name contains 'brave', so a bare pkill would hit them)".
- `AI-BRIEF.md` §5 trap 1: "**ALWAYS anchor to the throwaway profile path (`pgrep -f '/tmp/ziy-.*profile'`) or the exact executable, match first, then kill by PID**", cited to `recon-behavior.md` §Kill discipline and three proof docs. Every browser-booting proof restates it in its own header, with `MOZ_CRASHREPORTER_DISABLE=1` on every launch.

### Rule 6 — `/tmp` is reboot-volatile: knowledge lives in `replica/`, not in `/tmp`
A reboot on 2026-10-15 wiped `/tmp/firefox-src`, `/tmp/brave-src`, `/tmp/ziy-apply-test`, `/tmp/qrenv`, `/tmp/pzenv`, `/tmp/screens-tool` and the whole pre-reboot profile set; only re-created work and the `~/.cargo` / node toolchains in `$HOME` survived. Sources: `AI-BRIEF.md` §2, §2.2 (the ABSENT table naming the document that outlived each asset), and §5 trap 12, whose rules follow verbatim:
- "**Any asset worth keeping must be (a) consumed by a worker until its result is written into `replica/`** (a proof doc, a patch, an evidence row), **or (b) moved into the project tree.** Bytes that live only in `/tmp` are one reboot away from not existing."
- "**Before starting work that needs the engine source, CHECK whether the tree is still there** (`ls -d /tmp/firefox-src/firefox-156.0.1 /tmp/fxsrc/*.tar.xz`)." If gone, re-extract from a present tarball; if there is none, re-download with the documented resumable command (`curl -C - --retry 40 --retry-delay 2 --retry-all-errors --retry-max-time 7000 -o firefox-156.0.1.source.tar.xz https://ftp.mozilla.org/…`) and verify the sha512 in `AI-BRIEF.md` §2.1.
- "**NEVER start a second download while one is in flight.**" The `-C -` is the property that matters at 1 MB/s.
- `patches/README.md` and `compile-readiness.md` §2 apply the same idea to apply-verification: patches were applied to a `cp -a` copy (`/tmp/ziy-apply-test`), never to the source tree in place.

### Rule 7 — No local Gecko compilation. Ever
`deep-fork.md` §0 (Build policy, co-owner decision): "**This box is NEVER used to compile Gecko.** No `./mach build`, no `./mach configure`, no `autoconf`, no `rustc`/`cargo` builds of Gecko components, no `ccache`-heavy jobs. Not occasionally, not 'just once for a proof', not in the background." Compilation happens **only** on CI (`.github/workflows/build-gecko.yml`, `workflow_dispatch` or a tag push) or on a future self-hosted runner the co-owner registers explicitly. **Still allowed, because it is light:** `git apply` on `/tmp` copies, byte-level omni.ja patching, pref/layer checks, `tools/build-shell.sh`. Anything >~60 s of sustained CPU MUST run `nohup` + `nice`/`ionice` and be declared in its report; "unavoidable" means there is no CI path and no lighter way — it does not include a Gecko compile. **Why:** the co-owner uses this machine interactively; 4 cores with ~5.4 GB available, and the `libxul` link is a single ~5 GB process, so a multi-hour build would pin every core for 6–14 h and thrash swap. Restated as a hard policy in `patches/README.md` ("patch **authoring and applying** on this box is fine and expected … **Compiling is not**"), `AI-BRIEF.md` §3, and the workflow header.

### Rule 8 — Docs over guessing: read the engine source / MDN / official docs before iterating
- `architecture.md` §1.3: "All facts below were read from MDN and from the installed engine's own sources. Where Gecko and Chromium differ, the difference is stated explicitly because it drives the design." §0.4 lists the fetched BCD/MDN URLs with dates.
- `proofs-shell.md` §1.6: "**Read the engine's own source rather than bisecting prefs.**" The worked method: `strings` on the binary finds nothing, so the value is read out of `omni.ja → modules/AppConstants.sys.mjs` with the central directory parsed by hand.
- `patches/README.md` step 1 / `proofs-cpp-fingerprint.md` §2–§3: "Ground the change in real source first … Every claim about what the code does should be traceable to a line number"; the "Why prefs + JS cannot do it" sections justify a patch *because reading proved the pref layer could not reach it*.
- `proofs-fix-ci.md` §2.2: the configure graph is "quoted from the engine source"; a claim may rest on "(a) a direct grep/read of the engine source that shows the line, or (b) marked unverified".
- `search-plan.md`: 12 primary sources, one request each, cited with what each told us, plus live probes (206/200/429/504); the one source that failed (Software Heritage, TLS) is explicitly **not** used.
- `deploy.md`'s engine limits are each paired with the schema or doc they were read from (MDN `windows.CreateType`, MDN `commands`, the engine's own `ShortcutUtils.validate`, the policies schema).
- **The counter-example that proves it is enforced:** `AI-BRIEF.md` §5 traps 7–11 are every place a worker iterated without reading first — the omni.ja CRC in both headers, the `granularOverrides` JSON-array crash, the 30 000-rule quota dropping the whole ruleset, the IndexedDB storage scan finding nothing, `privacy.spoof_english` vs the real pref name.

## 3. PRODUCT DECISIONS LOG

### 3.1 The engine stack: Gecko by configuration + extensions (not Chromium/WebKit/from-scratch)
`architecture.md` §1.1: Firefox 156.0.1 **by configuration, not by patch** — (1) Ziy's own application directory (a controlled copy of the engine tree with Ziy's `application.ini`, `defaults`, `distribution/`, patched `omni.ja`), (2) a profile Ziy creates and owns (`~/.ziy/profiles/<name>`, never `~/.mozilla/firefox/…`), (3) an MV3 WebExtension suite, (4) a small native layer where extensions cannot reach. §1.2 records the rejected alternatives so they are not re-litigated: from-source Gecko fork (no passwordless sudo, 4-core/5.4 GB, 12–24 h), Firefox + unsigned extensions with no app dir (worse on every axis), a plain AMO extension (no rebranding, no locked prefs, no NTP), Chromium/Kiosk (out of scope by product decision). It is "not a fork of Brave's code … a clean-room product, designed from `replica/recon.md` only … The architecture is Brave's own product shape — engine + blocking engine." The engine layer has its own contract: omni.ja patches are length-preserving and CRC-correct in **both** headers (`tools/lib/omni-ja.py`; trap 7), and the C++ layer is gated and reversible. **Extension lib pattern:** UMD IIFE classic scripts for `background.scripts[]` — Gecko loads them as one HTML document of plain classic scripts, so `import`/`export` is a SyntaxError, a duplicate top-level `const` is a parse-time kill, and a bare `module.exports` is a ReferenceError. `ziy-sync` is the exception (`"type": "module"`, because its libs are genuinely ESM and shared with `native/` and `server/`). Source: `AI-BRIEF.md` §3; proof `proofs-fix-events.md` §1–§2, quoting `WebExtensionPolicy.cpp BackgroundPageHTML()`.

## 4. THE CLEAN-ROOM GUARD

### 4.1 `tools/lib/cleanroom-scan.py` — the code-level scan
Asserts no reference product's name appears as a **string literal** in shipped code — an identifier, a storage key, or a message a user would read.
- **Banned terms:** `"Brave"`, `"Google Chrome"`, `"Chromium"`, `"Mozilla Firefox"`.
- **Scope:** `extensions/`, `shell/`, `tools/` — the directories the product ships. `build/` (an engine copy), `node_modules/`, `__pycache__/`, `.git` are skipped. Text suffixes: `.js`, `.json`, `.css`, `.html`, `.py`, `.sh`.
- **Comments are excluded on purpose:** `strip_comments()` removes block, `//` and Python `#` comments first, because "a clean-room record is supposed to explain a deliberate divergence ('the generator is ours, not Brave's'), and that prose is the record working, not a leak."
- **Self-skipping:** the scanner and `verify.sh` (`SKIP_FILES`) are excluded — their job is to name the thing they check for.
- **Asserter lines are not leaks:** a line whose neighbouring window says `=== false`, `assert.`, `expect(`, `missing` or `absent` is skipped — the NTP suite's own clean-room test reads `["brave","leo","bat ","Chromium"]` and asserts each is absent; flagging that "would be the checker mistaking the proof for the crime".
- **Negative-tested.** `proofs-desktop.md` §5.3 planted a leak (`printf 'x"Brave"x' > extensions/ziy-desktop/leak-probe.js`) → exit 1, removed it → exit 0. It exists as a *file* rather than an inline heredoc because the heredoc version's quoting was eaten, so "the regex never compiled and no output meant 'no hits'" — the worst failure mode a check can have.

### 4.2 `tools/verify.sh` §12 — the other three classes
The guard "checks what a USER SEES, not what a DEVELOPER WROTE", and after stripping comments asserts four things: (1) **manifest identity strings** — every `extensions/*/manifest.json`'s `name`, `description`, `default_title`, `homepage_url`, `short_name`, and `action` / `sidebar_action` `default_title` / `default_panel` must not name another product; (2) **the .desktop entry's visible fields** — `Name`, `GenericName`, `Comment` of `shell/ziy.desktop` must name only Ziy (this found a real one: the `Comment=` read "a Brave-feature browser", rewritten to "a privacy-first browser on the Gecko engine"); (3) **shipped assets** — every `*.svg` under `brand/` and `replica/design/brand/` is grepped case-insensitively for `brave|chromium` (rasters carry no executable text and are exempt; SVG is text and is checked); (4) **the code-level witness** — §4.1.

### 4.3 The rule this enforces
**No competitor name, mark, or trade-dress appears in any shipped asset, or in any title / `aria-label` / user-visible string.** `replica/design/icon.md` header + §3 + §4.9: "No competitor name, mark, silhouette, animal or colour family may appear in any prompt, description, filename, or `<title>` inside shipped assets", and "If you edit a `manifest.json` `icons{}` block, add no name-bearing comment or string." `replica/design/brand/colors.md` and `brand/README.md` record that the mark is original Ziy work — a shield with a sealed eye — with "No other browser's mark, silhouette, animal, orange family, or typographic treatment … traced or referenced." The related discipline that is *not* a leak: Ziy's own code, labels and design are clean-room, and the `re-deep-*` docs are the record of *what* Brave does, "never a copy target for *how* Ziy does it" (`evidence.md`). Write every label fresh — "Matching what a button does is parity. Matching its sentence is copying." Also excluded by design, recorded so a worker does not re-add it: no JS bundle decompiled, no `.pak` unpacked (names and sizes only), no network traffic logged, no Brave account used; `screens/*.png` are design references only and live in `replica/screens/` "precisely so they are excluded from the product".

## 5. EVIDENCE DISCIPLINE

### 5.1 The confidence classes (`replica/evidence.md`)
Two axes — how the claim was obtained, and how far it can be pushed:

| class | meaning |
| --- | --- |
| **OBSERVED (behavioral)** | Driven against the user's own Brave Origin install over its own CDP endpoint, or against Ziy's own build; the claim was seen, not deduced. |
| **OBSERVED-SOURCE** | Read from Brave's public MPL-2.0 source (`brave/brave-core`, `brave/go-sync`, `brave/adblock-lists`, `brave/adblock-rust`) with a quoted file path and line range. Public code read **for understanding only** — Ziy's implementation is clean-room from the behavior contracts. |
| **OBSERVED-INSTALL** | Read out of the on-disk install / the user's own profile (their data, read-only), or captured from its running UI. |
| **DOC-INFERRED** | Taken from Brave's public documentation. Describes the intended product; can be stale or outranked by an OBSERVED row. |
| **BUILT-EXERCISED** | A Ziy artifact that was actually run and asserted on this machine. |
| **INFERRED** | Derived by reasoning from the above; no direct observation. |

Every row is dated. `recon.md`'s legend is the finer-grained sibling: `high` = stated in a source; `medium` = inferred from one or a partial source; `guess` = standard convention with no Brave-specific evidence; claims touched by the later passes carry the explicit **OBSERVED (behavioral)** / **OBSERVED-SOURCE** / **INFERRED** markers.

### 5.2 The contradiction-precedence rule
`evidence.md` "How to read a contradiction" — `recon.md` was written first from documentation only, then a behavioral pass and three source passes contradicted parts of it. The rule applied throughout:
1. **OBSERVED (behavioral) beats OBSERVED-SOURCE, which beats DOC-INFERRED.**
2. **A contradicted claim is never silently deleted.** It is struck through in place (`~~wrong claim~~`) with the correction and its confidence class beside it.
3. **Where a claim could not be observed at all** (the Shields panel's own rendering; the per-site request counts under a control load), it stays marked **STILL-INFERRED** and the miss is recorded "rather than being smoothed into an observation".

Worked examples: `recon-behavior.md` corrects cookie control to 2 states and "Simple vs Advanced view" to a single view plus an "Advanced options" disclosure; `recon.md`'s "No reference screenshots" row is struck through and corrected in the same edit; `parity.md` §2/§5 keep the old ranking struck through with `CLOSED 2026-10-15` beside it.

### 5.3 What is explicitly NOT evidence
`evidence.md` "Not evidence (explicitly)": no JS bundle decompiled or read; no `.pak` unpacked (names and sizes only); no network traffic logged; no Brave account used. `screens/` is design reference, never shipped.
